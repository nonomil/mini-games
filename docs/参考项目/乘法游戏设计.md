# 乘法启程 · 数学 PK 设计

## 目标

把乘法练习做成一段可以独立打开的短局体验：先通过“几组几个”的图形练习建立数量感，再进入和机器人同题竞速的数学 PK。玩家不需要依赖宠物积分总站，也不需要先理解复杂的积分规则，打开页面就能开始一题。

本设计以宠物积分系统已有的数学 PK 玩法为规则基线，保留它成熟的题目生成、机器人节奏、支援卡、结算复盘和奖励回传；独立小游戏只负责启动、资源路径、进度命名空间和页面壳层。

## 核心流程

```text
打开页面
  -> 默认进入“乘法启程”
  -> 选择“练习场”或“PK”
  -> 练习场：看点阵 -> 读“几组几个” -> 输入答案 -> 连对反馈
  -> 连对 5 题后提示“挑战机器人”
  -> PK：同一题竞速 -> 答对先手攻击 -> 5 轮后结算
  -> 展示得分、正确数、连击、星轨和下一局建议
```

练习场不是强制教程。玩家可以直接选择 PK；如果选择练习场，连续答对 5 题只用于提供清晰的进阶提示，不会锁死其他难度。

## 玩法规则

### 乘法练习场

- 每题展示 2-5 组、每组 2-5 个点阵。
- 题面同时展示重复加法和乘法表达式，例如“3 组，每组 4 个”“4 + 4 + 4 = ?”“3 × 4 = ?”。
- 玩家通过页面数字键盘或物理键盘输入答案，答对后点阵反馈并进入下一题。
- 答错时保留题面，明确显示“几组几个”的解释，并把连对重置为 0；“再试一次”支援卡可以保留本次连对。
- 连对达到 5 题后展示进阶提示，可以重新练习或挑战机器人。

### 机器人 PK

- 一局 5 轮，每轮玩家和机器人面对同一道题。
- 玩家答对且早于机器人完成，玩家赢得本轮并触发宠物攻击；超时则机器人赢得本轮并反击。
- 答错不会立即结束本轮，玩家可以清空输入后继续抢答；“再试一次”可以让机器人额外等待一次。
- 连续答对会增加本轮得分；最终按胜场决定整局胜负，并给出成长积分与星轨奖励。
- 乘法难度使用更宽松的机器人节奏，让准确理解优先于单纯提速。

## 难度

| ID | 名称 | 内容 | 适合状态 |
| --- | --- | --- | --- |
| `easy20` | 加减起步 | 20 以内加减 | 初次热身 |
| `easy100` | 加减进阶 | 100 以内加减 | 已经熟悉基础加减 |
| `medium_mul` | 乘法启程 | 基础乘法与点阵 | 正在理解乘法 |
| `medium_mix` | 综合闯关 | 加减乘混合，含应用题 | 想练题型切换 |
| `hard` | 乘除挑战 | 乘除混合，机器人更快 | 已经比较熟练 |

独立入口默认选择 `medium_mul`，但玩家选择过的难度会保存，下次打开时恢复。

## 支援卡

中阶玩法开始前可以选择一张支援卡：

- `看阵列`：乘法题显示紧凑点阵。
- `慢一点`：本局机器人每题多思考 2 秒。
- `再试一次`：本局第一次答错时不立即损失练习连对或额外延长抢答时间。

支援卡是学习脚手架，不改变题目答案，也不替代玩家输入。

## 独立运行约束

- 页面入口：`games/math-pk/index.html`。
- 启动脚本：`games/math-pk/game.js`，只负责独立页面初始化和默认难度，不复制 MathPKGame 规则。
- 玩法脚本：`vendor/js/math-pk.js`，复用宠物积分系统已提取的数学 PK 核心。
- 宿主适配：`host/petbank-host-shim.js`，提供没有主站时所需的最小 Profile、积分、排行榜和宠物接口。
- 进度键统一使用 `minigames_math_*`，避免独立项目写入宠物积分总站的 `petbank_math_*`。
- 资源通过小游戏项目根目录的 `assets/` 和 `data/` 加载；机器人素材使用 `assets/arena/math-rivals/`，应用题池使用 `data/math-cmath.json`。
- 在宠物积分总站 iframe 或新窗口启动时，仍通过 `bridge.js` 只回传完成事件，不把独立项目的本地进度交给主站管理。

## 体验与无障碍

- 数字键盘使用固定尺寸网格，桌面端和手机端都不因文字变化而跳动。
- 所有主要操作使用原生按钮，物理键盘支持数字、退格和回车。
- 顶部保留明确的返回游戏库入口；页面主体不依赖固定高度，窄屏允许自然滚动。
- `prefers-reduced-motion` 下关闭点阵、攻击和冲击动画。
- 颜色不是唯一反馈方式，答题状态同时用文字、分数和角色状态表达。
