# 小说改编内容包规范与接口草案

## 1. 目的

本文件冻结小说改编第一版的最小数据边界，供后续 `games/novel-adventure/` 运行时、内容校验器和内容作者使用。它是草案，只有在契约测试通过后才升级为稳定版本。

## 2. 内容包目录

```text
content/novel-adaptations/<project-id>/
  project-manifest.json
  characters.json
  scenes.json
  quests.json
  activities.json
  endings.json
  assets-manifest.json
  source-record.json
  ai-review-log.json
```

要求：所有 JSON 使用 UTF-8；ID 使用小写 ASCII、数字和连字符；展示文本可以使用中文；未知字段由运行时忽略但由校验器报告。

## 3. 项目 manifest

{
  "schemaVersion": 1,

### 4.1 支持的条件

```json
[
  {"type": "hasFlag", "key": "helpedMerchant"},
  {"type": "equals", "key": "trust", "value": 1},
  {"type": "gte", "key": "trust", "value": 2},
  {"type": "questStatus", "questId": "find-the-letter", "value": "completed"}
]
```

第一版不支持任意表达式、函数调用、网络请求和动态代码。

## 5. 活动接口

```json
{
  "activityId": "activity-01-letter",
  "nodeId": "activity-01-letter",
  "gameId": "word-shooter",
  "mode": "standalone-or-host",
  "domain": "english",
  "contentType": "word",
  "cardIds": ["story-card-01"],
  "payload": {
    "prompt": "输入信件中的口令",
    "returnContext": {
      "projectId": "public-short-story-001",
      "storyNodeId": "activity-01-letter",
      "returnNodeId": "scene-04-reward"
    }
  },
  "onComplete": "scene-04-reward",
  "onStop": "scene-02-market",
  "onError": "scene-02-market"
}
```

非学习类活动使用 `domain: "story"` 和 `cardIds: []`；英语、拼音、表达活动必须声明自己的内容域，不允许混用。

## 6. 保存和恢复

存档只保存可重建状态，不保存渲染 DOM、随机对象或临时计时器：

```json
{
  "schemaVersion": 1,
  "projectId": "public-short-story-001",
  "contentVersion": "1.0.0",
  "sessionId": "novel-session-001",
  "checkpointNodeId": "scene-02-market",
  "currentNodeId": "scene-02-market",
  "visitedNodeIds": ["scene-01-gate", "scene-02-market"],
  "flags": {},
  "counters": {},
  "questStates": {},
  "activityResults": [],
  "endingId": null,
  "updatedAt": 1785100000000
}
```

恢复规则：

1. `projectId` 不匹配时拒绝恢复。
2. `schemaVersion` 不兼容时进入新局，并记录原因。
3. `currentNodeId` 不存在时回退 `checkpointNodeId`。
4. 重复动作使用 `actionId + state revision` 去重。
5. `endingId` 非空时只能显示结局、再玩或返回入口。

## 7. 来源和 AI 审查

`source-record.json` 至少包含：来源标题、作者、版本/出版社或网址、获取日期、版权判断、允许使用范围、引用位置和审核人。AI 日志至少包含：模型、提示版本、输入文件、输出文件、生成时间、人工修改、审查结果和发布人。

任何 `inference` 或 `original` 内容都必须在内容编辑阶段明确标记；运行时不向用户展示内部审查字段，但验收报告要能追溯。

## 8. 静态校验规则

内容校验器必须覆盖：

- manifest 文件存在且版本合法。
- 所有 ID 唯一且符合命名规则。
- `startNodeId` 存在并可遍历。
- 所有 `nextNodeId`、条件、任务、角色、活动和资产引用存在。
- 至少一个 ending 可从起点抵达。
- 所有非 ending 节点存在离开动作，或明确为 checkpoint/terminal。
- 活动 `gameId` 在允许 manifest 中注册。
- `cardIds`、`domain` 和 `contentType` 组合合法。
- 没有未声明的远程资源、空地址或资源类型不匹配。
- 内容包没有超出项目简报声明的分级和改编范围。
