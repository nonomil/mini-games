# AI 学习教练与游戏化成长系统方案

## 1. 方案定位

参考项目“我把背单词小程序推倒重做，准备加入 AI 和游戏化成长系统”提出了三条主线：

1. 用间隔复习解决“今天会、明天忘”。
2. 根据错误、耗时和掌握情况调整学习节奏。
3. 用经验、等级、连胜、段位和勋章帮助孩子长期坚持。

这三条主线应当合入学习编排层，而不是直接写进苦力怕、飞机大战或拼音赛车的局内逻辑。

当前项目的分工如下：

| 能力 | 当前小游戏项目 | 卡片式单词学习游戏记忆系统 | 章节或农场包装层 |
| --- | --- | --- | --- |
| 角色、战斗、赛道、输入、碰撞 | 负责 | 不负责 | 不负责 |
| 单卡结果、错误标签、响应时间 | 采集并上报 | 归一化并保存 | 展示摘要 |
| 到期复习和掌握度 | 不负责 | 负责 | 展示推荐原因 |
| 每日新词/复习计划 | 不负责 | 负责 | 展示今日任务 |
| AI 例句、解释、弱项分析 | 提供错误上下文 | 调度和缓存 | 以孩子看得懂的方式展示 |
| XP、等级、连胜、勋章 | 可显示本局临时反馈 | 最终结算和持久化 | 包装成建筑、称号或装饰 |
| 章节解锁和世界变化 | 不负责 | 产出结算事件 | 负责表现结果 |

因此，当前小游戏项目可以独立运行，也可以被卡片系统作为外部宿主调用；它不需要依赖 AI 服务、Profile 或 FSRS 才能启动。

## 2. 参考内容与方案落点

| 参考项目中的想法 | 本方案的具体落点 | 第一责任方 |
| --- | --- | --- |
| 10 分钟、1 天、3 天、7 天、15 天、30 天、60 天复习 | 可解释的基础间隔表，按结果推进或回退 | 卡片记忆系统 |
| 总是答错的词要多出现 | 错误计数、错误标签、短间隔补强 | 卡片记忆系统 |
| 答对但思考时间太长 | `slow-independent-answer` 推荐原因 | 卡片记忆系统 |
| 每个人拥有自己的记忆曲线 | 先用规则计算，积累数据后再做个体化参数 | 卡片记忆系统 |
| 学一个单词获得 XP | 学习行为事件奖励，与掌握度独立 | 卡片记忆系统 |

| 连续 7 天学习 | 学习日 streak，不以游戏时长计算 | 卡片记忆系统 |

## 3. 每日学习计划

### 3.1 用户看到的结果

每日计划不再只显示“今天学习 100 个词”，而应告诉孩子三件事：

- 今天为什么出现这些卡片。
- 先做什么、预计需要多久。
- 完成后哪些内容会进入下一次复习。

建议计划对象采用以下结构：

```js
{
  planId: "plan-20260727-001",
  profileId: "profile-child-1",
  domain: "english",
  packId: "kindergarten",
  date: "2026-07-27",
  targetMinutes: 18,
  estimatedMinutes: 16,
  cards: [
    {
      cardId: "english:kindergarten:cat",
      source: "due-review",
      reason: "due-review",
      recommendedMode: "recognition",
      estimatedSeconds: 45
    },
    {
      cardId: "english:kindergarten:jump",
      source: "new",
      reason: "new-card",
      recommendedMode: "learning",
      estimatedSeconds: 60
    }
  ],
  generatedBy: "rule-v1",
  createdAt: 0
}
```

`planId` 和卡片顺序在计划生成后保持不变。孩子中途退出，下一次可以从未完成的计划继续，而不是重新随机一批词。

### 3.2 选词顺序

第一版使用确定性规则，保证推荐结果可解释、可测试、离线可用：

1. 先选本局刚答错且尚未补强的卡片。
2. 再选已经到期的卡片，越逾期优先级越高。
3. 再选最近两次答对但反应明显变慢的卡片。
4. 最后补充少量新卡，避免每天只复习旧词而没有新内容。
5. 达到时间预算后停止加卡，不为了凑数量强行延长学习。

推荐原因使用固定枚举：

| 原因 | 给孩子看的文案 | 触发条件 |
| --- | --- | --- |
| `recent-mistake` | 这张卡刚才有点难，再练一次 | 最近会话答错 |
| `due-review` | 到复习时间了 | `nextReviewAt <= now` |
| `overdue-review` | 这张卡已经等你一会儿了 | 超过计划时间 |
| `slow-independent-answer` | 你答对了，但再熟一点会更轻松 | 独立答对但耗时超过个人基线 |
| `new-card` | 今天认识一个新词 | 从未完成主动回忆 |
| `confusion-reinforce` | 这张卡和相似词容易混淆 | 命中混淆集或同类错误 |

### 3.3 预计时长

预计时长用于安排负担，不用于评价孩子聪不聪明。计算可以从简单规则开始：

```text
预计秒数 = 学习阶段基础时间
         + 题型时间
         + 历史耗时修正
         + 错误补强时间
```

建议初始值：

| 阶段 | 单卡基础时间 |
| --- | ---: |
| 学习卡 | 60 秒 |
| 识别 | 30 秒 |
| 输入 | 45 秒 |
| 错题补强 | 60 秒 |
| 到期复习 | 45 秒 |

实际使用时取最近三次独立答题耗时的中位数，并限制修正范围，避免某次走神把计划拉得过长。若预计超过目标时长，优先减少新卡，不减少刚到期或刚答错的复习卡。

计划页可以呈现：

```text
今日计划
复习 8 张 · 新学 3 张
预计 18 分钟
优先补强 2 张容易混淆的卡
```

参考项目中的“建议学习 18 个新词、复习 62 个单词、预计 18 分钟”应理解为产品展示示例，而不是固定配额。实际系统必须根据卡片数量、题型、个人历史耗时和目标时长重新计算；如果数量与时间冲突，优先保证到期复习质量，不强行凑数字。

数字只是计划提示，不应变成孩子必须完成的硬性指标。

## 4. 复习间隔与掌握度

### 4.1 基础间隔

先采用参考项目中的可解释间隔：

```text
首次主动回忆
  -> 10 分钟
  -> 1 天
  -> 3 天
  -> 7 天
  -> 15 天
  -> 30 天
  -> 60 天
```

这不是固定死的艾宾浩斯公式，而是一条容易理解和验证的默认轨道。后续可以用实际保持率校准，但必须保留推荐原因和调整记录。

### 4.2 结果到间隔的规则

| 本次结果 | 掌握度变化 | 下一次安排 |
| --- | --- | --- |
| 独立答对且耗时稳定 | 提高 | 进入下一档间隔 |
| 独立答对但耗时明显变慢 | 小幅提高或不变 | 保留短一档复习 |
| 提示后答对 | 不算独立掌握 | 维持当前档或提前复习 |
| 原题重试答对 | 记录为补强成功 | 不能直接跳过下一次复习 |
| 答错一次 | 降低稳定度 | 10 分钟或当天补强 |
| 连续答错 | 降低题型难度 | 先做识别/听辨，再回到输入 |
| 主动跳过 | 不增加掌握度 | 加入错题队列并记录 `gave-up` |

掌握度至少要区分：

- 是否独立答对。
- 是否使用提示。
- 是否延迟后仍然答对。
- 哪个维度出错：字母、声母、韵母、声调、释义或语境。

游戏分数、连击、游戏时长和装备不参与掌握度计算。

### 4.3 AI 不直接改掌握度

AI 可以判断“可能需要一个更简单的解释”，但不能直接把卡片标记为已掌握，也不能未经规则校验延长复习间隔。掌握度更新必须由结构化结果事件完成：

```js
recordAttempt({
  cardId,
  gameId,
  responseMode: "independent-input",
  result: "correct",
  hintUsed: false,
  responseMs: 4200,
  errorTags: []
})
```

## 5. AI 学习教练

### 5.1 分阶段建设

#### V1：没有 AI 也能正常学习

- 计划由本地规则生成。
- 释义、音频、例句和图片来自经过审核的内容包。
- 错误原因使用固定标签和固定模板。
- 网络不可用时，计划、游戏和复习都可用。

#### V2：AI 做内容辅助

- 根据错误标签生成更容易理解的例句。
- 解释拼写顺序、声母韵母、声调或语境区别。
- 生成一个联想提示，但不替代真正回忆。
- 将弱项整理成家长可读的摘要。

#### V3：AI 做计划解释和个体化建议

- 解释为什么今天复习这张卡。
- 根据预计时间建议“少学几张，但先完成到期复习”。
- 根据历史错误推荐下一种题型。
- 在章节主题下生成故事、任务或场景文案。

### 5.2 AI 的允许范围和禁止范围

允许：

- 生成解释、例句、联想、图片提示和弱项总结。
- 将结构化统计转成孩子能理解的短句。
- 为章节包装生成不影响答案的任务文案。

禁止：

- 直接修改 `mastery`、`nextReviewAt` 或 `independentCorrect`。
- 生成未经校验的正确答案并直接进入题库。
- 用游戏分数推断单词已经掌握。
- 为了提高留存故意增加不必要的学习量。
- 将儿童原始学习数据发送给没有明确授权的外部服务。

### 5.3 AI 请求与响应

请求只发送必要的结构化信息，不发送完整个人身份信息：

```js
{
  task: "explain-error",
  locale: "zh-CN",
  domain: "english",
  card: {
    word: "jump",
    translation: "跳",
    example: "I can jump.",
    errorTags: ["wrong-middle-letter"]
  },
  learnerLevel: "beginner",
  outputVersion: "coach-v1"
}
```

响应必须经过字段校验：

```js
{
  task: "explain-error",
  explanation: "先记住中间的 u，再读完整个单词。",
  example: "The cat can jump.",
  mnemonic: "jump 像是向上跳起来。",
  source: "ai",
  reviewed: false,
  expiresAt: 0
}
```

字段校验至少包括：非空、长度上限、不能覆盖标准答案、不能包含不适龄内容、不能把 AI 猜测写入卡片主数据。审核后的内容可以提升为内容包资产；未审核内容只能作为临时提示并带有版本号。

### 5.4 缓存与失败回退

AI 结果按 `task + cardId + errorTags + learnerLevel + outputVersion` 缓存，避免同一错误每次重复调用。缓存应记录生成时间和版本，词卡内容更新后失效。

失败时按以下顺序回退：

1. 使用内容包中已审核的解释和例句。
2. 使用固定模板解释错误标签。
3. 只显示正确答案、发音和原题重试。

AI 超时不能阻塞游戏结束、复习计划生成或奖励结算。

## 6. 游戏化成长系统

### 6.1 三条数据线分离

| 数据线 | 代表什么 | 允许影响什么 |
| --- | --- | --- |
| `learning` | 是否真的记住 | 复习间隔、题型和章节达标 |
| `growth` | 是否持续参与 | XP、等级、装饰和称号 |
| `achievement` | 是否完成长期目标 | 勋章和展示页 |

三条数据线可以在结果页同时展示，但不得互相覆盖。

### 6.2 XP 规则

参考项目中的“学习一个单词 +2 EXP、连续答对 +5 EXP”可以作为首版规则：

| 行为 | XP | 限制 |
| --- | ---: | --- |
| 完成一次有效学习卡动作 | +2 | 同一张卡同一阶段同一会话只算一次 |
| 独立答对并完成一张卡 | +2 | 提示后答对只获得基础参与奖励 |
| 连续答对达到 3、5、10 张 | +5 | 每个里程碑每个会话只触发一次 |
| 完成今日计划 | +10 | 至少完成计划中的复习部分 |
| 连续学习 7 天 | +30 | 每个 7 日里程碑只触发一次 |

XP 结算必须使用幂等的 `rewardReceiptId`。刷新页面、重复发送 `complete` 或重复打开结果页，不能重复获得奖励。

不建议按按键次数、游戏时长、失败次数或重复刷同一张卡发放 XP。这样会把孩子引导到“玩得久”而不是“记得住”。

### 6.3 等级和段位

等级是累计参与成长，段位是长期稳定学习表现，两者都不代表单词掌握度。

等级可以使用简单可解释的阈值：

```text
Lv1: 0 XP
Lv2: 100 XP
Lv3: 250 XP
Lv4: 450 XP
Lv5: 700 XP
后续每级增加 250 + 50 * (等级 - 5) XP
```

段位建议使用近 30 天的“延迟独立答对积分”，而不是累计 XP：

| 段位 | 建议条件 |
| --- | --- |
| 青铜 | 初始段位 |
| 白银 | 近 30 天完成至少 3 次到期复习 |
| 黄金 | 近 30 天延迟独立答对率达到 60% |
| 铂金 | 近 30 天延迟独立答对率达到 75% |
| 钻石 | 近 30 天延迟独立答对率达到 85% |
| 王者 | 延迟独立答对率达到 90%，且至少有 4 周有效数据 |

如果数据不足，不降段、不显示虚假的精确评价，只显示“继续积累复习记录”。

### 6.4 连续学习

连续学习按“有效学习日”计算，不按打开应用次数计算。一天满足以下任一条件即可计入：

- 完成当天计划中的到期复习。
- 完成至少 3 张卡的主动回忆。

建议规则：

- 连续 3 天：显示小型里程碑。
- 连续 7 天：发放连续学习奖励和勋章进度。
- 连续 30 天：发放长期坚持勋章。
- 漏学一天只中断当前 streak，不清除历史总学习天数和已获得勋章。
- 时区变化、设备时间明显回拨或重复提交同一天事件时，不重复计算。

### 6.5 勋章清单

勋章条件必须能解释、能复现、能从事件记录追溯：

| 勋章 | 条件示例 | 关联事件 |
| --- | --- | --- |
| 坚持达人 | 累计 7 个有效学习日 | `learning-day` |
| 单词大师 | 30 张卡完成至少一次延迟独立复习 | `delayed-correct` |
| 拼写达人 | 20 张英语卡独立输入首答正确 | `independent-input` |
| 早起冠军 | 7 个不同日期在本地 06:00-09:00 完成有效学习 | `learning-day` + 时间段 |
| 夜猫子 | 7 个不同日期在本地 21:00-23:00 完成有效学习 | `learning-day` + 时间段 |
| 连续 365 天 | 连续 365 个有效学习日 | `learning-day-streak` |

早起和夜间勋章是可选展示，不应暗示某个时间段比另一个时间段更优秀。涉及儿童的时间数据只保留勋章所需的聚合结果，不保存不必要的详细位置或设备信息。

## 7. 四个小游戏的接入方式

小游戏只上报学习事件和局内统计，XP、连胜和勋章由宿主最终结算：

| 游戏 | 学习事件重点 | 推荐成长反馈 | 不应承担 |
| --- | --- | --- | --- |
| 苦力怕 | 英语逐字输入、首答、错位字母、提示使用 | 拼写里程碑、守住基地的装饰奖励 | 修改复习间隔、发放长期勋章 |
| 飞机大战 | 英语主动输入、目标命中、漏目标、响应时间 | 连续命中反馈、章节任务奖励 | 用击落数量判断掌握度 |
| 拼音赛车 | 汉字、拼音、声母、韵母、声调的独立判断 | 赛道解锁、车辆外观、拼音挑战徽章 | 把拼音结果写入英语词卡 |
| 网球学英语 | 释义、例句和表达选择、语境错误 | 表达章节积分、主题场景装饰 | 直接替代英语单词拼写证据 |

宿主收到 `card-result` 后，按以下顺序处理：

```text
游戏提交单卡结果
  -> 校验 sessionId、gameId、cardId
  -> 写入 learning attempt
  -> 更新复习计划
  -> 计算 XP、连胜和勋章事件
  -> 生成 reward receipt
  -> 返回章节或农场包装层
```

当前小游戏项目在没有宿主时可以显示本地临时分数，但必须把它标记为本局奖励，不把它伪装成卡片系统的长期成长数据。

## 8. 建议接口

学习系统可以先提供以下接口，游戏只依赖其中与自己有关的部分：

```js
getDueCards({ domain, packId, limit, now })
buildDailyPlan({ profileId, domain, packId, targetMinutes, now })
getCoachAdvice({ cardId, errorTags, learnerLevel, locale })
recordAttempt({ cardId, gameId, sessionId, result, responseMs, hintUsed, errorTags })
recordGrowthEvent({ profileId, type, source, idempotencyKey })
getGrowthSnapshot({ profileId })
listEarnedBadges({ profileId })
```

游戏宿主协议仍然只使用 `ready`、`init`、`card-result`、`complete`、`stop`。AI 和成长接口不应通过游戏 iframe 暴露给任意页面，避免游戏绕过宿主直接写入 Profile。

## 9. 分阶段实施

### P0：规则和数据底座

- 保存 `nextReviewAt`、`nextReviewReason`、`intervalDays`、`responseMs` 和错误标签。
- 实现到期卡、新卡、错题和慢答卡的确定性排序。
- 实现幂等的学习事件和奖励 receipt。
- 让结果页显示预计下次复习时间和推荐原因。

### P1：每日计划和成长反馈

- 增加每日计划对象和预计用时。
- 实现 +2 XP、连对里程碑 +5、7 日 streak 和基础等级。
- 增加“复习本局错题”和“继续今日计划”入口。
- 为拼写、延迟复习和连续学习建立勋章进度。

### P2：AI 内容辅助

- 接入错误解释、例句、联想和弱项摘要。
- 加入响应校验、缓存、版本和内容审核状态。
- 网络失败时自动使用本地模板。

### P3：个体化教练

- 用历史响应时间和保持率校准个人基线。
- 根据弱项推荐题型顺序和章节补强任务。
- 评估 AI 建议是否减少重复错误，而不是只统计调用次数。

## 10. 验收标准

### 学习计划

- [ ] 今日计划显示复习数、新词数、预计用时和推荐原因。
- [ ] 刚答错的卡优先于普通新卡。
- [ ] 计划中断后能从原 session 继续，不重新随机整组卡。
- [ ] AI 不可用时仍能生成计划并完成复习。

### 学习与成长隔离

- [ ] XP、等级、连胜和勋章不会修改掌握度或下一次复习时间。
- [ ] 游戏分数、连击和时长不会直接变成掌握度。
- [ ] 提示后答对与独立答对分别统计。
- [ ] 重复发送结果不会重复发放 XP 或勋章。

### AI 教练

- [ ] AI 不能覆盖标准答案或直接写入掌握度字段。
- [ ] AI 响应有版本、缓存和审核状态。
- [ ] AI 超时不会阻塞游戏完成和奖励结算。
- [ ] 儿童数据只发送完成任务所需的最少字段。

### 长期成长

- [ ] 连续 7 天、30 天和 365 天都有可追溯事件。
- [ ] 早起和夜猫子勋章不会互相贬低。
- [ ] 数据不足时不显示虚假的段位精度。
- [ ] 卡片系统和章节包装层都能读取同一份成长快照。
