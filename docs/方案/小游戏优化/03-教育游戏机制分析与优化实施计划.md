# 教育游戏机制分析与优化实施计划

> **给执行者：** 必须先按本文件的 Task 顺序实施；代码行为变更使用测试驱动开发，先写失败测试，再写最小实现。

**目标：** 把当前“学习内容触发答对/答错反馈”的小游戏集合，逐步改造成“学习目标进入玩家决策、决策改变游戏后果、失败推动策略调整”的教育游戏系统；本轮先完成拼音巡航第一条可验证垂直切片。

**架构：** 保留现有静态页面、原生 JavaScript、拼音卡片域模型和 `pinyin-runtime`，不重写整套游戏。先把学习决策、提示代价、路线后果和复习状态收敛到可测试的 runtime，再由独立入口消费同一套行为，避免独立 `game.js` 与 runtime 各维护一套学习循环。

**技术栈：** 原生 JavaScript ES modules、Node.js `node:test`/`assert` 风格契约测试、浏览器静态页面、现有 Canvas/DOM 赛道基础设施。

## 1. 分析结论

本计划参考 `G:/UserCode/跨平台采集器/notes/学习/好的教育桌游，不是把题目贴在棋盘上.md` 中的判断方法：

1. 学习目标是否被翻译成玩家必须做出的选择。
2. 选择是否承担与学习目标相关的后果。
3. 失败是否引发策略调整，而不是只扣分或停一轮。
4. 替换学习主题后，机制是否仍然原封不动。
5. 玩完后是否能解释选择、代价和概念，而不只是谈输赢。

当前项目的工程基础已经完整，但教育机制呈现分层状态：

| 模块 | 当前强项 | 当前问题 | 判断 |
| --- | --- | --- | --- |
| 单词像素探险 | 中文炸弹、英文目标、命中/失误、护盾、错词复习 | 主要是语义匹配；支援道具和自动瞄准可绕开学习判断 | 局部嵌合，策略不足 |
| 消灭苦力怕 | 每个字母输入就是攻击，记录错误位置和复习队列 | 战斗后果与词义无关；换成任意字符串也能运行 | 拼写熟练度练习 |
| 拼音星际巡航独立入口 | 按声母/韵母顺序收集，收错掉星并缩短蛇身 | 顶部直接显示完整拼音；实际入口没有使用新的 `pinyin-runtime` | 有嵌合潜力，但存在答案暴露和集成断层 |
| 拼音 `pinyin-runtime` | 题型、错误维度、路线分叉、暂停、复习位置恢复、学习指标 | 路线分叉尚未由学习决策触发，更多是预集成基础设施 | 本轮优先落地 |
| 数学 PK | “几组几个”阵列图、机器人速度、重试支援 | PK 仍然是算答案后获得攻击；数学策略不改变局面 | 概念引导型答题 |
| 网球学英语 | 意义/搭配/语境错误标签，区分独立答对与提示答对 | 三选一仍是核心动作，网球主要承担反馈包装 | 高质量答题练习 |
| 森林/故事地图与卡牌 | 探索、故事、队伍、技能、物品和长期成长 | 学习活动是地图之外的节点，主题可替换而不破坏战斗 | 动机与进度层 |

项目当前更接近“完整的学习练习平台”，而不是所有玩法都已经达到嵌合式教育游戏。内容数量、资源规模、协议完整性不能替代学习机制证据。

## 2. 本轮范围

### 2.1 本轮要完成

以 `games/pinyin-star-scout/pinyin-runtime.js` 为核心，完成下面的可验证行为：

- 学习题型明确决定当前路线设施的任务类型。
- 玩家提交正确学习决策后，才可以选择或进入与该决策相关的路线分支。
- 选择分支会改变实际路线长度、风险或可用恢复机会。
- 错误答案进入复习队列，并保留原始赛道位置；复习正确后恢复原路线状态。
- 显示完整答案或使用提示要产生可观察的提示代价。
- session snapshot 能恢复题型、路线选择、提示次数和复习状态。
- 独立入口至少消费共享的“隐藏答案/提示代价”状态，不再把完整拼音作为默认任务答案展示。

### 2.2 本轮不做

- 不一次重写 `learning-arcade`、单词地图、数学 PK 或卡牌战斗。
- 不引入 Three.js、后端、账号系统或新的状态管理框架。
- 不把长期掌握度写入小游戏协议；长期学习调度仍由宿主或共享学习层负责。
- 不删除现有旧入口，先以兼容方式接入并保留回滚路径。
- 不用单纯加快车速制造学习难度。

## 3. 目标行为模型

本轮将拼音巡航的核心循环收敛为：

```text
看到汉字/听音
  -> 判断声母、韵母或声调
  -> 选择安全路线/捷径路线
  -> 路线长度、风险和奖励发生变化
  -> 错误时暂停并复习同一张卡
  -> 复习成功后恢复原位置并继续
```

示例：当前题型是 `initial-choice` 时，玩家不是单纯点击“正确答案得一分”，而是要在分叉点选择与声母判断对应的路线。答错会进入复习并保留卡片，复习成功才能恢复赛道进度。

## 4. 技术设计

### 4.1 Runtime 状态

在不破坏现有 snapshot 的前提下增加可选字段：

```js
{
  questionType: "initial-choice",
  routeDecision: {
    segmentId: "initial-final-fork",
    expectedBranchId: "inner",
    selectedBranchId: "wide",
    accepted: true,
    consequence: "long-route"
  },
  hint: {
    uses: 1,
    revealed: false,
    penalty: 0
  },
  reviewQueue: [
    {
      cardId: "pinyin:starter:mountain",
      position: { distance: 110, lane: 0 },
      errorTag: "wrong-initial",
      attempts: 1
    }
  ]
}
```

字段要求：

- `routeDecision` 只记录本局决策和后果，不写长期掌握度。
- `hint.uses` 可恢复、可统计；提示不能悄悄改变正确性。
- `reviewQueue` 保留原卡片赛道位置，复习正确后恢复该位置。
- 旧 snapshot 没有新增字段时使用默认值，保证刷新和历史状态兼容。

### 4.2 学习决策与路线绑定

新增最小 runtime API：

```js
runtime.getRouteDecision();
runtime.chooseLearningRoute({ segmentId, branchId, response });
runtime.useHint({ mode: "paused" });
```

行为规则：

- `chooseLearningRoute` 必须先用当前 `questionType` 评估 `response`。
- 正确响应才允许选择学习路线，并记录 `accepted: true`。
- 错误响应进入 `reviewQueue`，路线不切换，时钟暂停。
- 选择非推荐分支仍可继续，但记录相应后果，例如 `long-route`，使策略选择有意义而不是单一正确/错误闸门。
- 不能重复提交同一张活动卡片结果。

### 4.3 独立入口兼容

独立 `games/pinyin-star-scout/game.js` 目前是自有蛇形循环，计划分两步迁移：

1. 本轮先删除默认完整拼音暴露，改为“汉字 + 语音 + 当前待拼片段”的渐进提示；通过提示按钮显式揭示完整拼音，并扣除本轮星星或独立答对奖励。
2. 后续再把蛇形移动和 `pinyin-runtime` 的路线、复习、碰撞状态完全接通。

本轮不修改蛇形核心碰撞规则，避免把多个高风险变化混在一次改动里。

## 7. 后续 P1/P2 路线

### P1：复制嵌合模式

- 单词地图：把“语义分类/目标优先级”绑定到敌人行为和资源分配，降低自动瞄准的默认权限。
- 数学 PK：把“几组几个、凑十、拆分策略”绑定到攻击方式或防御资源，而不只是显示阵列图。
- 打字防线：保留主动拼写，但让词义、词形和错误位置改变目标行为；将复习策略纳入下一轮编排。

### P2：建立跨游戏教育证据层

- 统一记录 `decision`、`consequence`、`strategyRevision`、`independentCorrect` 和 `reviewTransfer`。
- 在结果页展示“我做了什么选择、造成什么结果、下一次怎么调整”，而不是只显示分数和连击。
- 为每个玩法增加主题替换测试和至少一个真实学习目标的迁移测试。
- 地图、卡牌、宠物系统只作为动机和进度层，不承担未经验证的学习效果声明。
