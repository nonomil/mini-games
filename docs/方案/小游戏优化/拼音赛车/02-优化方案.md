# 拼音赛车优化方案

## 1. 优化目标

拼音赛车应当成为“汉字到拼音的识别、辨析和输入训练”。移动车子接卡片的学习动作可以保留，但赛道必须从固定背景重构成真正持续运动的代码赛道；难度也需要从“车速变快”扩展为识别、听辨、声母/韵母辨析和完整输入等不同学习目标。

## 2. 当前主要问题

### P0：当前更像识别游戏，不是拼音输入游戏

目前玩家主要通过移动小车选择卡片，输入函数只处理上下左右。它可以训练“看到汉字选拼音”，但不能证明孩子能独立写出拼音。

建议明确分成两条路线：

1. 认拼音：看汉字、听音、接正确卡片。
2. 写拼音：看汉字或听音，输入完整拼音。

不要用一个模糊的“拼音难度”同时代表两种能力。

### P0：声调数据不够稳定

当前 `normalizePinyin()` 会删除声调符号，并且部分去重逻辑使用标准化后的拼音。这样适合检索，却不适合训练声调。显示值、语音值和比较 key 必须分开保存。

### P0：结果页复习只是文字展示

结果页的“复习一下”目前只取本局最后几项并拼成一段文本，不能点击复习，也不会在下一局或下一次会话中优先出现。

### P0：反应速度可能压过拼音学习

参考英语赛车项目的复盘，赛车的天然门槛是反应速度；如果拼音卡片过快、车道碰撞窗口过窄，孩子可能因为来不及换道而答错，结果记录的是手眼协调失败，而不是拼音判断失败。

需要把三个变量分开：

- 学习正确率：是否选择或输入了正确拼音。
- 反应表现：看到题目后用了多久完成选择。
- 操作表现：是否成功换道、碰撞是否发生。

基础模式应优先保证看清题目、听清声音和完成判断，车速只在挑战模式中逐步增加。

### P0：固定背景让它不像赛车

当前实现已经有多张赛道 WebP 图片、CSS 透视和 DOM 设施，但这些内容主要是静态舞台：

- `WORD_CANNON_MAPS` 通过 `asset` 字段切换整张背景图。
- `renderWordCannonStage()` 把当前图片写入 `--cannon-stage-image`。
- CSS 使用 `background-size: cover` 铺满 `.pinyin-race-stage`。
- `updateWordCannon()` 主要推进拼音卡的 `target.y`，没有推进赛道中心线、弯道、路旁物体和镜头。

所以玩家看到的是“固定画面里的卡片在移动”，而不是“车辆在赛道里前进”。继续增加背景图只能增加主题数量，不能解决赛车感。建议把赛道本体改成代码生成，固定图片降级为菜单缩略图、天空纹理或赛段装饰。

### P0：当前赛道和学习任务没有真正绑定

代码中虽然有 `s-bend`、`fork`、`bridge`、`tunnel`、`finish-sprint` 等段落名称，但它们主要控制卡片布局和 CSS 样式。优化后每个赛段都要成为可运行的赛道数据：它有长度、曲率、宽度、坡度、车道数、地标和对应题型，玩家的路线选择会改变后续路段和反馈，而不是只改变一个 `data-segment` 属性。

### P1：基础干扰项容易通过排除法解决

基础难度倾向于使用不同声母、不同长度的干扰项。孩子不一定真正听清或读对，只要排除明显不相似的选项就能答对。

### P1：长局会稀释学习目标

基础模式 8 题可以接受，但进阶和完整模式继续增加到 16/24 题时，应该按赛段结算，而不是做成一条很长的连续过程。

### P1：素材质量和提示语言还可以分层

英语赛车参考项目强调使用精选词汇和英文释义。拼音赛车也不应只从大词库随机抽题，应优先使用当前课程、绘本或主题词包，并为每张卡准备汉字、拼音、声调、音频、例词或短句。对于低龄用户使用中文提示，对于熟练用户再开放简单汉语解释或全拼音提示，避免提示语言本身成为额外障碍。

## 3. 目标体验

### 基础：认汉字接拼音

1. 显示一个大汉字、图片或短例句。
2. 播放汉字发音，可选播放拼音发音。
3. 三张卡片从上方或前方进入。
4. 玩家把车移到正确拼音卡所在车道。
5. 答错时车辆减速，正确卡片闪烁并播放发音。
6. 同一目标立即进入一次低速重试。

基础模式的卡片应有足够的可见时间；如果孩子正在听音或阅读例句，赛道可以暂时减速或暂停。完成拼音判断后再恢复前进，不用让阅读速度和手指速度互相竞争。

### 进阶：声母/韵母辨析

题目不只问完整拼音，而是明确问一个维度：

- “这个字的声母是什么？”
- “哪个卡片的韵母正确？”
- “哪一张卡和示范音相同？”

干扰项应当有针对性，不能只随机抽其他拼音。

### 挑战：输入完整拼音

1. 显示汉字、图片或播放声音。
2. 车子自动沿赛道前进，孩子需要输入拼音。
3. 输入正确时加速，错误时减速但不立即失败。
4. 完成拼音后进入下一道卡或选择声调。
5. 结果页区分“认对”和“写对”。

## 4. 题型和难度

| 难度 | 目标 | 干扰项 | 操作 |
| --- | --- | --- | --- |
| 基础 | 完整拼音识别 | 不同声母、相同长度 | 三车道选择 |
| 标准 | 声母或韵母辨析 | 同声母不同韵母，或相反 | 选择 + 短语音 |
| 进阶 | 声调辨析 | 同音节不同声调 | 选择声调卡 |
| 挑战 | 完整拼音输入 | 错误后显示局部提示 | 屏幕键盘或系统键盘 |

### 干扰项生成规则

按学习阶段生成，而不是全部随机：

1. 基础阶段：避免过于相似，先保证能建立正确反馈。
2. 标准阶段：使用同声母或同韵母的最小对比。
3. 进阶阶段：加入声调相同音节和声调不同音节。
4. 错词复习：优先选择孩子曾经混淆过的声母、韵母或声调。

干扰项必须保留原始拼音展示值，例如 `shān`、`shán`、`shǎn`、`shàn`；标准化 key 只用于程序比较，不能替代显示和语音数据。

## 5. 赛道代码化重构

### 5.1 技术方向

建议使用 `Canvas 2D + DOM 学习卡片` 的混合实现：

- Canvas 负责赛道、路面、车道线、路旁地标、车辆阴影、速度线和碰撞区域。
- DOM 继续负责汉字、拼音卡、提示、按钮和无障碍文本，保证文字清晰、可点击和可读屏。
- 第一版不需要完整 3D 引擎。用二维路径采样、透视投影和分层绘制，就能实现连续弯道、坡道、隧道和分支。
- 只有在需要真实三维模型、复杂摄像机和大量动态物体时，才评估 Three.js；不要为了赛道变化一开始引入过重的渲染栈。

### 5.2 赛道世界模型

把当前的固定地图改成由数据描述的连续路段：

```js
{
  id: "forest-curve-01",
  type: "curve-right",
  length: 420,
  curvature: 0.42,
  roadWidth: 180,
  laneCount: 3,
  elevation: 0.08,
  surface: "forest-road",
  landmark: "听音隧道入口",
  taskType: "sound-gate",
  correctRoute: "inner",
  recoveryRoute: "wide",
  decorations: ["tree", "sign", "light"]
}
```

赛道由多个路段连接而成，例如：

```text
起步直道
 -> 缓弯
 -> 声母分叉
 -> 下坡
 -> 听音隧道
 -> 声调桥
 -> S 弯
 -> 终点冲刺
```

每局根据词包、难度和随机种子生成一条可复现的路线。刷新或复盘时使用同一个种子，避免孩子看到的题目和地形突然变化。

### 5.3 透视和运动模型

不需要把所有东西画成真实 3D，但必须有“远处小、近处大、经过镜头后离开”的空间关系。推荐为每个路段采样中心线点，并把车辆和地标放在赛道坐标上：

- `distance`：物体沿赛道前进的距离。
- `lateral`：物体相对赛道中心线的横向偏移。
- `lane`：物体所属车道。
- `height`：桥、坡道或跳台的高度。
- `roadWidth`：当前位置的路面宽度。

渲染时按物体与摄像机的距离计算屏幕位置和缩放：

```text
赛道坐标 -> 路段中心线采样 -> 摄像机相对距离
 -> 透视缩放 -> 屏幕 x/y -> 车辆、卡片和地标绘制
```

这样车辆前进时，车道线可以从远处变粗，弯道中心线可以连续偏移，路旁树木和路牌可以从屏幕下方经过，而不是让一张背景图永远停在原位。

### 5.4 可运行的赛道形态

| 路段 | 视觉变化 | 学习作用 |
| --- | --- | --- |
| 直道 | 车道线连续靠近，适合读题 | 汉字到完整拼音识别 |
| 左/右弯 | 赛道中心线连续偏移，车辆轻微侧倾 | 声母或韵母选择 |
| S 弯 | 左右连续变向，路旁标志交替出现 | 相似拼音快速辨析 |
| 分叉 | 两条路实际分开，正确路更短或奖励更好 | 选择正确声母/韵母 |
| 上坡/下坡 | 地平线和路宽发生变化 | 听音辨析，降低卡片速度 |
| 隧道 | 视野变窄，灯光沿中心线移动 | 听音到拼音 |
| 桥 | 路面悬空，桥墩随距离经过 | 声调选择 |
| 终点门 | 目标门从远处接近并穿过镜头 | 完整拼音输入或本段结算 |

### 5.5 学习卡片如何进入真实赛道

拼音卡不再只是独立的 HTML 元素向下移动，而是一个挂在赛道坐标上的目标：

1. 目标卡拥有 `distance`、`lateral`、`lane` 和 `segmentId`。
2. 卡片位置由赛道投影计算，随着车辆和摄像机推进自然变大、偏移和经过。
3. 三个选项可以放在三条真实车道上；分叉题可以把正确选项放到捷径路段。
4. 卡片碰撞判断使用赛道距离和横向距离，不再只用屏幕坐标的固定阈值。
5. 答错后赛道暂停，正确卡片回到可读位置，完成短复习后再继续前进。

固定背景图仍可保留，但只作为地图选择页的缩略图、天空/远景层或赛后海报，不再承担赛道运动本体。

### 5.6 时钟和暂停

代码赛道需要使用 `requestAnimationFrame` 和固定时间步长，而不是让 `setInterval` 同时承担物理、题目和渲染：

- `simulationClock`：车辆、赛道、目标和碰撞。
- `learningClock`：阅读、播放语音和复习提示，答题时可以暂停。
- `renderClock`：每帧绘制画面，不参与掌握度计算。

孩子阅读汉字、播放声音或查看错误反馈时，赛道应进入学习暂停状态；暂停时可以保留风吹、灯光和车辆轻微待机动画，但不能继续推进目标和扣除操作时间。

### 5.7 当前实现的迁移方式

不要一次性重写所有玩法，建议分三步迁移：

1. 保留现有 DOM 卡片和学习判断，先用 Canvas 绘制一条可连续前进的直道，替代固定背景。
2. 把 `PINYIN_RACER_SEGMENTS` 转成代码路段，加入弯道、坡道、隧道和路旁地标；目标卡从 `x/y` 坐标迁移到 `distance/lateral`。
3. 最后加入分叉、捷径、碰撞边界、摄像机跟随和赛道种子生成，删除对整张背景图的依赖。

| 赛道设施 | 学习动作 | 答错反馈 |
| --- | --- | --- |
| 声母弯道 | 选择正确声母 | 正确声母高亮，车辆减速 |
| 图片补给站 | 图片到拼音 | 显示图片和正确拼音 |
| 声调桥 | 选择声调 | 播放两次示范音并标出调号 |
| 听音隧道 | 听音到拼音 | 重播声音并降低车速 |
| 终点拼读门 | 输入完整拼音 | 显示已输入部分和下一位 |

地图主题不再只是换背景。每条路线最好绑定一个训练主题：

- 草地 S 弯：声母入门。
- 云桥分叉：声母和韵母选择。
- 森林隧道：听音辨析。
- 糖果声调桥：四声辨认。
- 终点冲刺：完整拼音输入。

主题差异由路段组合、地标、颜色、天空层和音效表达；核心路面、碰撞规则和学习反馈保持一致。

## 6. 错误处理

当前“答错后立即生成同题重试”的方向正确，可以进一步细化：

### 第一次错误

- 车辆短暂停止。
- 正确卡片放大并播放发音。
- 显示“这个字读作 X”。
- 下一波只保留正确卡和一个简单干扰项。

### 第二次错误

- 在汉字旁显示声母、韵母或声调提示。
- 将错误标签记录到词卡，例如 `wrong-tone`。
- 进入低速重试，不扣长期奖励。

### 结果复习

- 错误词显示为可点击卡片。
- 点击后进入单词/拼音复习小页面。
- 复习顺序为：看字选拼音 -> 听音选拼音 -> 输入拼音。

## 7. 车子操作

### 桌面端

- 左右键换道。
- 上下键控制靠近或远离卡片。
- 可选 `A/D/W/S`，但要和飞机大战的控制约定保持一致。
- 触碰正确卡片时自动吸附，减少像素级碰撞挫败。

### 移动端

- 赛道底部保留四向按钮。
- 支持点击车道直接换道。
- 支持左右滑动，但滑动不能触发页面滚动。
- 题目、拼音卡和控制按钮不能互相遮挡。
- 触控区域最小 44px，错误反馈不能单独依赖颜色，应同时显示文字、音效或动画。

## 8. 赛段和奖励

推荐把一局拆成三个 2-3 题的赛段：

```text
赛段 1：认汉字接拼音
 -> 赛段 2：声母/韵母辨析
 -> 赛段 3：错词重试或拼音输入
 -> 终点结算
```

每个赛段结束显示一次小结，不要让孩子在 24 题结束后才第一次看到学习反馈。

### 反应速度的使用边界

建议提供三个可见模式，而不是用一个速度参数代表全部难度：

| 模式 | 车速 | 学习目标 | 计分依据 |
| --- | --- | --- | --- |
| 学习 | 慢速或可暂停 | 看清、听清并认出拼音 | 拼音判断正确 |
| 标准 | 稳定速度 | 在有限时间内完成选择 | 正确率为主，速度为辅 |
| 挑战 | 逐段加速 | 处理相似声母、韵母和声调 | 正确率、反应和操作分开显示 |

“挑战”不能通过单纯加速制造难度。若孩子连续因操作失误答错，应降低车速或扩大碰撞窗口，而不是把错误直接写入拼音掌握度。

奖励可以区分：

- 接到正确卡：基础金币。
- 第一次就接对：额外星星。
- 提示后重试成功：基础星星，不算独立掌握。
- 下一次会话仍能答对：稀有奖励。

## 9. 数据和代码建议

### 拼音卡字段

```js
{
  cardId: "pinyin:level-1:山:shān",
  char: "山",
  pinyinDisplay: "shān",
  pinyinKey: "shan",
  initial: "sh",
  final: "an",
  tone: 1,
  audio: "...",
  example: "我们一起去爬山。"
}
```

### 局内任务字段

```js
{
  cardId: "pinyin:level-1:山:shān",
  taskType: "tone-choice",
  source: "mistake",
  wrongDimension: "tone",
  hintUsed: 0,
  retryCount: 0,
  completedBy: "choice", // choice | typing
  startedAt: 0
}
```

### 建议拆分的职责

- `pinyin-card.js`：拼音拆分、声调和干扰项生成。
- `pinyin-session.js`：新词、错词和到期词编排。
- `pinyin-racer-input.js`：车道、触控、键盘输入。
- `pinyin-racer-track-spec.js`：直道、弯道、分叉、桥、隧道等路段数据。
- `pinyin-racer-track-generator.js`：根据词包、难度和随机种子生成可复现路线。
- `pinyin-racer-track-renderer.js`：Canvas 赛道、路面透视、摄像机和路旁地标。
- `pinyin-racer-physics.js`：车辆速度、横向移动、路面边界、目标碰撞和分叉路线。
- `pinyin-racer-stage.js`：赛道段落与学习设施状态的绑定。
- `pinyin-racer-learning.js`：错误维度和复习记录。

当前逻辑集中在 [`game.js`](../../../../games/learning-arcade/game.js)，优先抽出赛道生成、渲染和学习判断，避免把固定背景、UI 文案、赛道动画和学习判断继续耦合。

## 10. 验收清单

- [ ] 基础模式明确是“认拼音”，挑战模式明确是“写拼音”。
- [ ] 声调显示值、语音值和比较 key 分离保存。
- [ ] 选择题干扰项能针对声母、韵母和声调生成。
- [ ] 答错后会播放正确音并立即重试原题。
- [ ] 错题可在结果页点击进入复习。
- [ ] 错词会在下一次会话优先出现。
