# 拼音赛车 P2 宿主接线交接方案

## 1. 交接结论

当前拼音专属 runtime、Canvas 赛道、学习时钟、快照和预集成 fixture 已完成；P2 的真实共享入口仍未完成。

真实运行时由以下清单定义：

- `gameId`: `pinyin-racer`
- `entry`: `games/learning-arcade/index.html`
- `runtime.hostId`: `learning-arcade`
- `runtime.mode`: `word-cannon`
- `domains`: `['pinyin']`
- 共享入口所有者：SHOOTER；最终确认者：主控

本交接方案不把 `games/pinyin-star-scout/index.html` 的独立页面验收当作共享入口接线证据，也不修改 `games/learning-arcade/game.js`、`bridge.js` 或 `host/`。

## 2. 已有协议依据

接线只能复用以下现有能力和字段：

1. `host/mini-game-host-protocol.md` 定义的 CORE v1 envelope。
2. `tests/fixtures/contract-v1-fixture.mjs` 的字段和值形状。
3. `window.MiniGamesBridge` 的 `ready`、`reportCardResult`、`error`、`complete`、`stop`、`registerCleanup` API。
4. `host/manifests/pinyin-racer.game-manifest.json` 的清单身份和 legacy 兼容边界。

不得把 `source/kind/sessionId/seq/payload.activeGame` 的旧消息当作 CORE v1 消息；旧消息只保留兼容回归用途。

## 3. 目标运行时顺序

### 3.1 启动

宿主创建或恢复 session 后，向 `games/learning-arcade/index.html` 传入稳定的 `sessionId` 和 `gameId=pinyin-racer`。拼音赛车初始化完成后发送：

```js
MiniGamesBridge.ready({
  sessionId,
  gameId: 'pinyin-racer'
});
```

ready 必须使用 `cardId: null`，只能发送一次；独立模式没有宿主身份时，游戏继续本地运行且不伪造 ready。

### 3.2 初始化卡片

宿主发送 `init` 时，卡片必须同时满足：

- envelope `cardId` 为非空原始卡片 ID；
- `payload.card.cardId` 与 envelope 的 `cardId` 完全相同；
- `payload.card.domain` 为 `pinyin`，缺失或其他 domain 都拒绝；
- `payload.card.contentType` 为 `pinyin`，或由清单规则明确补齐；
- 拼音字段保留 `char`、`pinyinDisplay`、`pinyinKey`、`initial`、`final`、`tone`，不得只保留去掉声调的 key；
- `payload.returnContext` 和 `payload.snapshot.returnContext` 都保留宿主传入值。

接收成功后，运行时只将这张卡装载到当前拼音题目，不读取英语输入缓冲、英语章节进度、英语 FSRS 或共享 reward 字段。

### 3.3 卡片结果

当前卡完成后，先提交一次 `card-result`，再决定是否结束本次宿主 session：

```js
MiniGamesBridge.reportCardResult({
  cardId: currentCard.cardId,
  payload: {
    domain: 'pinyin',
    contentType: 'pinyin',
    correct: Boolean(result.correct),
    responseMode: result.responseMode,
    questionType: result.questionType,
    errorTag: result.errorTag || null,
    reactionMs: result.reactionMs,
    returnContext
  }
});
```

同一 `sessionId + cardId` 的第二次提交必须被 bridge 拒绝；运行时不得通过重新 mount、刷新或旧卡引用绕过幂等限制。错误复习应先产生拼音卡的错误结果，再在本地 session 中恢复原路线位置。

### 3.4 完成和停止

完成所有宿主卡后发送一次 `complete`：

```js
MiniGamesBridge.complete({
  payload: {
    domain: 'pinyin',
    resultCount,
    score,
    stars,
    metrics,
    returnContext
  }
});
```

宿主发送 `stop` 或页面销毁时，运行时必须停止 `requestAnimationFrame`、语音、计时器和路线输入，并通过 `registerCleanup` 注册可验证的清理函数。stop 后不得再提交 card-result、complete 或旧 legacy completion。

## 4. returnContext 规则

`returnContext` 是宿主上下文，不是题目答案，也不是局内随机状态。接线应遵循以下规则：

- 从 `init.payload.returnContext` 读取并保存；
- snapshot 恢复时保留同一个对象的可序列化内容；
- `card-result`、`complete`、`stop` 的 payload 继续带回同一上下文；
- 不将 `returnContext` 写入 `profile`、章节掌握度或英语进度；
- 不把 URL、随机 session ID 或页面序号写入上下文后冒充宿主字段；
- 无宿主上下文的独立模式使用 `null` 或不发送宿主消息，不生成伪造的返程地址。

## 5. 接线任务清单

| ID | 任务 | 负责方 | 完成条件 | 状态 |
| --- | --- | --- | --- | --- |
| P2-H01 | 在共享入口读取 `pinyin-racer` 的宿主身份 | SHOOTER | `sessionId/gameId` 稳定传入拼音赛车 runtime | pending |
| P2-H02 | 拼音卡 domain/contentType 校验 | SHOOTER | 非拼音 init 被拒绝，原始 `cardId` 保留 | pending |
| P2-H03 | ready/init 生命周期接线 | SHOOTER | ready 一次，init 后当前卡和 snapshot 可观察 | pending |
| P2-H04 | card-result 结果回传 | SHOOTER | 正误、题型、错误标签、metrics 和 returnContext 可核对 | pending |
| P2-H05 | complete/stop/cleanup | SHOOTER | 两个终态均幂等，动画/语音/计时器全部清理 | pending |
| P2-H06 | 跨游戏回归 | SHOOTER + 主控 | 英语 word-shooter、typing-defense 和拼音均通过共享契约 | pending |
| P2-H07 | 主控浏览器验收 | 主控 | 宿主真实发送 init，页面真实回传 card-result 和 complete | pending |

## 6. 验收矩阵

| ID | 验收方法 | 必须看到的证据 | 失败即拒收 |
| --- | --- | --- | --- |
| P2-A01 | 清单/静态检查 | `domains` 只有 `pinyin`；runtime 身份与共享入口一致 | 接收英语卡或修改清单身份 |
| P2-A02 | 宿主消息日志 | ready、init 顺序正确，身份字段匹配 | 只有旧 `source/kind` 消息 |
| P2-A03 | domain 隔离测试 | 英语卡、缺 domain 卡、冻结非拼音卡全部拒绝 | 非拼音卡进入 runtime |
| P2-A04 | 结果回传测试 | 每张卡恰好一次 card-result，`cardId` 原样保留 | 只发局级 complete 或 cardId 丢失 |
| P2-A05 | 上下文比较 | init、card-result、complete、stop 的 returnContext 可序列化且一致 | 上下文丢失或被运行时改写 |
| P2-A06 | 幂等/刷新测试 | 重复 result、刷新后旧卡 result、重复 complete 均拒绝 | 刷新造成重复奖励或重复结果 |
| P2-A07 | stop/timeout 测试 | 动画帧、语音、定时器停止；终态拒绝新消息 | 页面仍推进或继续回传 |
| P2-A08 | 浏览器验收 | 宿主页真实接线，桌面/移动视口无回归 | 仅 fixture 或独立页截图 |

## 7. 必跑命令

在共享入口代码完成后，按以下顺序执行：

```text
node tests/test-pinyin-racer.mjs
node tests/test-pinyin-host-adapter.mjs
node tests/test-pinyin-scout-session.mjs
node tests/test-pinyin-preintegration.mjs
node tests/test-pinyin-race-visuals.mjs
node tests/contract-cross-game-protocol.mjs
node tests/contract-lifecycle.mjs
npm test
git diff --check
```

专项和 fixture 通过只能证明独立模块与协议形状正确；只有 P2-A02、P2-A04、P2-A05、P2-A08 在真实 `games/learning-arcade` 页面中取得证据后，任务清单才可从 `review / fixture-only` 改为 `verified`。

## 8. 当前交接风险

- 现有 pinyin preintegration fixture 已覆盖 CORE v1 envelope，但 `ownership.status` 仍为 `fixture-only`。
- `games/learning-arcade/game.js` 当前仍保留 legacy `activeGame` 边界，不能以静态正则或独立拼音页替代真实宿主接线。
- 本线程不修改共享入口；P2 真实接线必须由 SHOOTER 实施并由主控复核后回写状态。
