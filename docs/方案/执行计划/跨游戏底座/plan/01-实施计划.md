# 跨游戏底座实施计划

**目标：** 为苦力怕、飞机大战、拼音赛车、网球学英语和探索地图提供同一种宿主生命周期与结果事件格式，同时保持所有游戏的独立入口。

**架构：** 游戏本体只负责局内运行和单卡结果；宿主负责传入卡片 session、校验消息、更新卡片系统和结算奖励。协议必须能在没有卡片系统时被本地 fixture 驱动。

**写入范围：** `host/`、`bridge.js`、跨游戏协议测试、`game-manifest.json` 示例和本工作流文档。不得修改任何游戏内部玩法文件。

## 步骤

### CORE-P0-01：现状盘点

- 阅读 `host/petbank-host-shim.js`、`bridge.js`、`games/*/index.html` 和现有 contract tests。
- 列出已有 `petbank.bridge.v1` 消息与目标通用协议的差异。
- 输出兼容字段表，不在此步骤修改业务代码。

### CORE-P0-02：清单和卡片标准化

- 为苦力怕、飞机大战、拼音赛车建立清单；网球清单由 TENNIS 提供后复核。
- 标准化 `cardId/word/translation/image/audio/example/domain/contentType`。
- 未知字段忽略，缺少可选字段时使用空值或本地回退。

### CORE-P0-03：生命周期桥接

- 实现或补齐 `ready/init/card-result/complete/stop/error`。
- 强制带 `protocolVersion/sessionId/gameId/cardId`。
- `card-result` 对同一 `sessionId + cardId` 幂等。
- `stop` 后不得继续提交结果。

### CORE-P0-04：安全和恢复测试

- 校验 `origin`、`sessionId`、`gameId` 和消息类型。
- 覆盖重复结果、未知卡片、宿主刷新、宿主停止和超时。
- 运行 `npm run test:contract` 和完整 `npm test`。

### CORE-P0-05：交接

- 在 progress 中写入协议版本、变更文件和测试输出。
- 通知 CREEPER、SHOOTER、TENNIS、MAP 可使用的 fixture。
- PINYIN 只使用协议字段，不修改共享桥接实现。
