# 小说改编网页游戏实施计划

> **给执行线程：** 必须先阅读本计划、`task/01-任务清单.md`、`验收标准/01-验收矩阵.md`、`docs/方案/小游戏优化/01-综合架构方案.md` 和 `host/mini-game-host-protocol.md`。完成每项任务后更新自己的 task、progress 和日志，不得使用 `README` 文件名。

**目标：** 在当前小游戏项目上实现一个内容包驱动的小说剧情网页游戏最小垂直切片，并为探索地图、现有小游戏和可选卡片系统接入保留稳定边界。

**架构：** 小说内容包提供稳定 ID、节点、条件、效果、活动和结局；纯状态运行时负责确定性状态转移；浏览器 UI 负责渲染和输入；活动适配器通过现有 host v1 或独立模式启动小游戏。卡片系统不作为独立小说运行的依赖，长期学习状态仍由卡片系统负责。

**技术栈：** Vanilla JS、HTML、CSS、JSON、Node.js 契约测试、现有本地静态服务、浏览器真实交互验收、`postMessage`/host v1。

---

## 实施边界

### 允许新增

- `games/novel-adventure/` 通用剧情运行时。
- `content/novel-adaptations/<project-id>/` 一个最小示例内容包。
- `tests/test-novel-content-contract.mjs`、`tests/test-novel-adventure.mjs` 和专属测试夹具。
- `host/novel-content-schema.json` 或等价的内容契约文件。
- `tools/novel-adaptation/` 的离线校验/构建脚本。

### 默认禁止

- 不修改四个小游戏的玩法核心。
- 不修改 `bridge.js` 的 v1 envelope 来加入小说专属字段。
- 不读取或写入卡片系统的 Profile、FSRS、奖励和章节 storage key。
- 不在运行时调用 AI 生成答案、奖励、状态或结局。
- 不把探索地图改成第二套剧情状态机。

运行：`node tests/test-novel-content-contract.mjs`

## 任务 2：纯剧情状态机

**文件：**

- 创建：`games/novel-adventure/story-state.js`
- 创建：`tests/test-novel-adventure.mjs`

**步骤 1：编写失败测试**

- 覆盖创建新状态、进入节点、条件不满足、设置 flag、增减计数器、任务状态、活动结果、结局、重复动作和序列化恢复。

**步骤 2：运行测试确认失败**

运行：`node tests/test-novel-adventure.mjs`

预期：模块不存在或行为未实现导致失败。

**步骤 3：实现最小确定性状态函数**

- 只支持方案中声明的节点类型和条件类型。
- 所有状态更新返回新对象，不直接改变调用方对象。
- 动作使用 `actionId` 去重；活动结果使用 `activityId + resultId` 去重。
- 不允许任意表达式、网络请求和 AI 调用。

**步骤 4：运行测试确认通过**

运行：`node tests/test-novel-adventure.mjs`

预期：正常路径、分支路径、坏输入和恢复路径均通过。

## 任务 4：浏览器剧情垂直切片

**文件：**

- 创建：`games/novel-adventure/index.html`
- 创建：`games/novel-adventure/runtime.js`
- 创建：`games/novel-adventure/story-renderer.js`
- 创建：`games/novel-adventure/styles.css`
- 修改：`tests/test-novel-adventure.mjs` 或新增浏览器专属测试

**步骤 1：先让 Node 契约覆盖 UI 所需状态**

- 入口、场景、对话、选择、活动等待、结局、重玩和错误状态必须都能由状态机表达。

**步骤 2：实现最小 UI**

- 移动端优先，提供清晰的场景标题、正文、角色、动作按钮、当前任务和返回入口。
- 使用占位素材也必须有稳定尺寸、加载失败文本和无横溢出约束。

**步骤 3：启动真实本地服务并验收**

运行：`npm run serve`

预期：真实浏览器打开小说入口，完成入口 -> 选择 -> 活动占位 -> 返回 -> 结局 -> 再玩。

**步骤 4：记录证据**

- 记录桌面和 `360x800` 的真实浏览器动作、截图、布局数据和失败原因。
- 不把 Node 或 fixture 结果写成浏览器通过。

## 任务 5：活动适配器和探索地图返回

**文件：**

- 创建：`games/novel-adventure/activity-adapter.js`
- 创建：`tests/test-novel-activity-adapter.mjs`
- 视需要局部修改：`games/explore-map/` 的入口或适配文件

**步骤 1：编写失败测试**

- 测试 `gameId/sessionId/cardId/payload.returnContext` 映射。
- 测试 complete、stop、error 返回到正确剧情节点。
- 测试非学习活动不伪造 cardId，拼音活动保持 `domain: pinyin`。

**步骤 2：运行测试确认失败**

运行：`node tests/test-novel-activity-adapter.mjs`

预期：缺少适配器时失败。

**步骤 3：实现最小适配器**

- 只使用 host v1 已有字段和 `payload` 扩展。
- 不修改共享 bridge，不读取外部项目 storage。
- 保存原剧情 node、task、project 和 return URL。

**步骤 4：运行测试确认通过**

运行：`node tests/test-novel-activity-adapter.mjs && npm test`

预期：小说专项和现有全局回归均通过，且无越权修改。
