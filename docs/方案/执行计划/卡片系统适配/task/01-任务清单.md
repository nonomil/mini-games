## 第一版映射建议

1. 以 `protocolVersion: 1`、`sessionId`、`gameId`、`domain`、`contentType` 为通用 envelope 字段；保留当前 `source/kind/payload` 作为 Word Quest v1 兼容外壳。
2. `sessionId` 由卡片系统 session 生成并进入 init；结果必须原样带回，宿主按 `sessionId + gameId + cardId` 校验和幂等。
3. 初版 `sourceGame -> gameId` 映射为：`word-racer -> word-shooter`、`pixel-word-adventure -> pixel-word-adventure`、`creeper-typing -> typing-defense`、`air-battle-typing -> word-shooter`、`pinyin-racer -> pinyin-racer`；当前四个 legacy source 只作为入站别名。
4. `mode` 继续映射到 `recognition`/`typing`，新增 `domain`/`contentType` 路由校验；英语、拼音、表达题不允许通过默认游戏回退混用。
5. `hintsUsed` 只作为 legacy summary 输入别名；标准单卡字段统一为 `hintUsed`，并在 P1-02 继续保留 `errorTags`、`operationErrors` 和响应时间。
6. `complete` 只表示本局结束，不表示章节完成；章节进度、FSRS 和 reward receipt 继续由 router/session/progress/rewards 负责。
7. 生产环境将 `targetOrigin` 从 fixture 当前的 `*` 收紧为宿主配置值，并增加消息来源、session、gameId 校验；CORE-P0-03 已 verified，但真实跨项目接入仍需真实小游戏接线和运行验证。

## ADAPTER-P2-01 边界契约

- `card-result` 先归一化为可解释学习事件：`eventId/sessionId/gameId/sourceGame/sourceStage/cardId/correct/grade/independent/hintUsed/responseMode/responseMs/errorTags/operationErrors/returnContext`；adapter 不计算 XP、等级、连胜或勋章。
- host 将唯一学习事件交给注入的 growth delegate；delegate 返回 `points/experience/level/streak/badges`，host 只把 `points/experience` 按既有 `rewards.claim` schema 形成 receipt，成长展示元数据留在 request/宿主边界，不新增 Profile key 或改变既有 receipt 规则。
- receipt 使用稳定 `sessionId + gameId + growth` eventId；恢复或重复 card/complete 不重复生成学习事件和 reward receipt，stop 后 adapter 和 message listener 均不再提交。
- AI coach 是可选解释来源。成功返回解释和例句；provider 缺失、抛错或返回无效内容时，回退到确定性解释、卡片例句和原计划，`degraded/reason` 可观察，不阻塞游戏或每日计划。
- 每日计划继续由既有 progress/session 规则调度：balanced 先取到期/错词，再从下一可用组补少量新词；review 不混入新词，challenge 不解锁章节。fixture 不写入这些业务状态。
- 本节证据是卡片系统 host/fixture contract；真实外部小游戏、真实 AI provider 和成长服务尚未接线，不能将 fixture 通过解释为跨项目完成。
