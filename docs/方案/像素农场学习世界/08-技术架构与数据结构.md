# 08 技术架构与数据结构

## 1. 实施原则

第一阶段不迁移 Phaser、Three.js 或其他引擎。当前项目已经有可运行的 Vanilla JS 游戏，先补共享数据与运行能力即可。

建议新增共享模块：

```text
vendor/js/world-state.js       地图、地块、作物、离线成长
vendor/js/learning-memory.js   词卡熟练度、到期复习、错词队列
vendor/js/world-input.js       键盘、Pointer Events、虚拟摇杆
vendor/js/asset-loader.js      版本化资源、懒加载、失败回退
vendor/js/session-resume.js    当前局保存与恢复
data/worlds/*.json             各主题农场配置
data/crops/*.json              作物、成长时间、奖励
data/learning/*.json           词包映射和复习规则
```

共享模块只负责稳定的数据契约，不把所有小游戏强行改成同一套 DOM。

## 5. 存储策略

- `localStorage`：设置、角色选择、声音开关、轻量摘要。
- IndexedDB：地块、作物、词卡复习、当前局和奖励记录。
- 主站 bridge：只回传完成事件和奖励结果，不共享主站积分命名空间。
- 每次重要动作后保存，页面隐藏或 `pagehide` 时再保存一次。

当前 `games/word-memory-map/game-storage.js` 主要保存关卡、奖励、复习词和角色选择，下一步需要加入当前局与世界状态。

## 6. 性能改造

- 默认先加载 starter/core，不在首次启动强制加载 all。
- 当前 `games/word-memory-map/index.html` 会把缺少 `vocab` 的访问改成 `vocab=all`，建议改为 core 默认、用户选择后再加载 all。
- 将 28 MB 级别的 PNG 背景转换为 WebP/AVIF，并保留视觉等价校验。
- 桌面和移动使用不同尺寸资源，使用 `srcset` 或 manifest 选择。
- 生产静态资源使用版本化 URL 和长期缓存；开发环境才使用 `no-store`。
- `dist_verify*` 等验证产物不要进入正式发布目录。
- 增加 PWA manifest 和 Service Worker，至少缓存应用壳、starter 词包和当前地图。

## 7. 外部章节宿主兼容边界

当前项目的小游戏应保持独立运行，同时预留被外部章节学习系统调用的 host 模式。外部宿主可以注入一组卡片并接收标准化结果，但不应让当前项目直接依赖章节、Profile、复习算法或奖励模块。

详细边界、消息协议、适配器接口和章节包装方式见：[小游戏底层与章节学习系统综合方案](../小游戏优化/01-综合架构方案.md)。
