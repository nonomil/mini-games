# 像素农场学习世界 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在当前小游戏项目中建立一个可恢复、移动端友好、以单词学习推动农场成长的多地图像素学习世界。

**Architecture:** 保留当前 Vanilla JS 多游戏结构，在 `vendor/js` 增加世界状态、词卡复习、输入和恢复模块；用 `data/worlds`、`data/crops` 和 `data/learning` 配置森林、太空、外星农场。先完成森林农场的垂直切片，再以配置和共享系统扩展其他地图。

**Tech Stack:** HTML/CSS/Vanilla JavaScript、JSON manifest、localStorage、IndexedDB、Pointer Events、Service Worker、Node.js contract tests。

## 分工原则

- 产品/学习：定义每张词卡的学习证据、任务目标和奖励含义。
- 运行时：负责状态、输入、存档、跨地图切换和错误恢复。
- 内容/美术：负责地图配置、作物、NPC、背景和一致的像素规范。
- QA：负责 Node 契约、浏览器冒烟、360x800 和 390x844 移动端验收。

单人推进时按“运行时 -> 学习 -> 内容 -> 视觉 -> QA”顺序执行；多人或多代理时只并行无共享文件的配置和测试任务。

## 全局 Definition of Done

一个任务只有同时满足以下条件才算完成：

1. 任务列出的文件已创建或修改，未扩大范围。
2. 任务对应的自动化检查已通过。
3. 关键用户流程至少在桌面和一个移动视口手工验证。
4. 存档、刷新、返回和异常资源路径有明确行为。
5. 验收结果写入 `09-推进状态.md`，并记录未解决风险。
