# 数学冒险首版方案

## 1. 设计原则

### 清楚的主线

主线使用“篇章 -> 关卡 -> 题目”的层级，不使用“全量难度 -> 模式 -> 支援卡 -> 题目”的多层选择。

### 有趣的战斗

关卡答题使用宠物攻击敌人的表现，让每一次答题都有可见结果；题目区域始终是页面的视觉中心。

### 每天有理由回来

每日随机 PK 提供固定时长、固定次数和当天奖励，形成低负担的回访任务。

### 失败可恢复

答错不使用“失败结束”作为主要反馈，而是收集错题、允许错题再战，并让孩子知道下一步做什么。

## 2. 页面结构

### 2.1 数学冒险首页

首页采用单一主面板，不做卡片墙：

```text
顶部：数学冒险 / 今日 PK 状态
主体：当前篇章的关卡地图
底部：加法篇 | 乘法篇 | 错题本
突出动作：继续当前关卡
次要动作：今日随机 PK
```

首页需要显示：

- 当前篇章名称。
- 当前关卡名称和完成进度。
- 关卡节点的解锁状态。
- 今日 PK 是否已完成。
- 错题本待练题数量。

首页不显示：

- 复杂的能力分析图。
- 多个并列的奖励进度条。
- 一次性展示所有题型、难度和支援卡。

### 2.2 关卡地图

每个篇章是一条横向或纵向的短路径，节点数量控制在 5-6 个。当前节点突出显示，已完成节点显示完成标记，未解锁节点只显示轮廓。

关卡节点只需要三种状态：

- 未开始：可进入。
- 已完成：可重复进入。
- 未解锁：显示通往它的下一步。

不加入分支地图、装备树和角色养成树。

### 2.3 关卡答题页

答题页采用稳定的三段结构：

```text
顶部：返回 / 关卡名 / 进度 / 生命值
中部：敌人、题目、攻击反馈
底部：三个答案按钮 / 状态提示
```

题目、答案按钮和生命值使用固定尺寸，避免反馈动画或文字变化造成页面跳动。

加法题可以使用数量合并、点数或简单图形作为辅助；乘法第一章必须支持分组图，让“几组几个”可视化。

### 2.4 每日 PK 页

每日 PK 使用原有竞技台的主体结构，但减少入口前的解释：

- 顶部显示“今日 PK”和剩余状态。
- 两侧为宠物和机器人。
- 中央显示当前题目。
- 答对触发攻击和比分变化。
- 5 轮结束后显示比分、正确数、错题数和今日奖励。

结算页只保留三个动作：

- 再看错题。
- 返回冒险。
- 明天再来。

## 3. 视觉方向

### 3.1 总体气质

采用“清晰的游戏工具”方向：深蓝灰背景作为舞台，使用明亮的黄色表达进度和主要行动，使用绿色表达答对，使用红色表达受击或敌人状态。

目标是低龄友好但不幼稚：少量角色、大面积留白、清楚的数字、有限的装饰。

### 3.2 颜色角色

| 角色 | 建议用途 |
| --- | --- |
| 深蓝灰 | 页面背景、竞技台和地图底色 |
| 柔和蓝 | 答案按钮和次要面板 |
| 明亮黄 | 继续、通关、每日 PK 和进度 |
| 绿色 | 答对、已完成、生命恢复 |
| 红色 | 敌人、受击、答错提示 |
| 近白色 | 题目数字和主要文字 |

颜色不能单独承担状态表达，答对和答错同时使用文字、图形或动作反馈。

### 3.3 角色与敌人

- 首版使用一个宠物和一组可替换敌人即可。
- 敌人变化优先体现在颜色、表情和受击状态，不急于制作大量角色。
- 攻击动画短、明确、可跳过，不能盖住题目和答案。
- 不使用大面积粒子、漂浮装饰或持续背景动画。

## 4. 交互与数据模型

### 4.1 主线进度

```js
{
  addition: { unlockedStage: 1, completedStages: [1], currentStage: 2 },
  multiplication: { unlockedStage: 0, completedStages: [], currentStage: 1 },
  wrongAnswers: { addition: [], multiplication: [] },
  dailyPk: { date: "YYYY-MM-DD", completed: false, result: null }
}
```

主线进度和每日 PK 状态分开保存。每日 PK 每天重置完成状态，但不重置主线解锁和错题本。

### 4.2 每日题目抽取

题目生成器接收三个输入：

- 当天日期种子。
- 已解锁的加法关卡范围。
- 已解锁的乘法关卡范围。

生成器不接收任意全局难度值，避免抽到主线范围之外的题目。

## 5. 反馈节奏

单题反馈控制在短暂、可预测的节奏内：

```text
选择答案
  -> 立即显示对错
  -> 宠物攻击或受击
  -> 更新生命/进度
  -> 进入下一题
```

答错时不弹出大遮罩。正确答案、简短提示和“这题已加入错题本”放在题目下方，保证孩子仍能理解发生了什么。

## 6. 参考图验证重点

GPT 参考图只验证方向，不作为最终实现截图。重点观察：

- 加法篇和乘法篇是否一眼能区分。
- 今日 PK 是否足够突出但没有抢走主线位置。
- 关卡地图是否比难度卡更易理解。
- 题目和答案是否比角色、装饰更醒目。
- 页面是否有游戏感，但没有回到“按钮、卡片、徽章全部堆在一起”的问题。

## 7. 实现顺序

1. 先完成首页、篇章切换和关卡地图。
2. 再把加法篇和乘法篇的关卡数据接入现有答题引擎。
3. 再接入共用错题本。
4. 最后把原有 PK 包装成每日随机 PK，并接入每日奖励。
5. 角色变身、更多攻击动作和音效作为后续增强，不阻塞首版可玩流程。
